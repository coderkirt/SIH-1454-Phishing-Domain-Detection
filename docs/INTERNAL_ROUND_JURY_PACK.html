6. Decision engine vs fusion

URL path — decision engine

Used by URLChecker. Confirmed intel is a floor. Heuristics cannot wash a feed hit down to LOW. ml_score is the lexical/heuristic URL score copy.

Message path — weighted fuse

url 0.22, domain 0.16, ml 0.10, nlp 0.10, psychological 0.10, threat_intel 0.10, brand 0.08, sender 0.05, community 0.05, redirect 0.04. Starting defaults, not proven-optimal. Then raise the floor if a child URL was confirmed malicious.

Levels: LOW 0–29 · MEDIUM 30–49 · HIGH 50–69 · CRITICAL 70–100. scam_risk is the same integer, not a calibrated probability. model_confidence = 35 + 10 × (signals ≥ 20), cap 95.

F. 40 viva questions — spoken answers

Repeat the question in five words, then answer. One person answers. If you do not know: “That is not in our current build. Today we do X. It is on the roadmap.”

Q1. What is PHISHEYE?
Say: A multi-channel phishing and scam intelligence prototype: a React website, a Chrome Manifest V3 extension, and one FastAPI brain that scores URLs, pasted messages, QR codes, and the browser tab in Simple English and Technical evidence.
If they push back: If they say it is just a VirusTotal clone: we add lookalike heuristics, Hinglish psychology, an explainable decision engine, and a scan-before-open gate. We do not claim we replace national intel.
Q2. What is SIH1454?
Say: NTRO asked for an intelligent system using AI/ML to detect phishing domains that imitate the look and feel of genuine domains. Software track, Blockchain and Cybersecurity theme. We implemented cybersecurity.
If they push back: If they read the word AI/ML: intelligence today is multi-signal fusion plus threat intel plus lookalike heuristics. A supervised model is phase two after curated labelled reports.
Q3. Where is the AI?
Say: Explainable fusion, public threat feeds, and lookalike heuristics. There is no neural net in this repository. The fusion channel named ml is a copy of the lexical URL score so a low ML number cannot be used as proof of safety.
If they push back: If they demand a CNN file: there is no SavedModel, no sklearn pickle, no BERT. Show url_checker.py, decision_engine.py, risk_engine.py.
Q4. Why FastAPI, not Flask?
Say: The live API is FastAPI with Uvicorn. Pydantic validates bodies. /docs is automatic Swagger for the jury. Flask is not the running backend.
If they push back: If an old comment says Flask: leftover naming. Open http://127.0.0.1:8000/docs.
Q5. Is the database PostgreSQL?
Say: Planned for multi-user production. Live today is SQLite file backend/threats.db. SQLAlchemy model files exist but live queries use sqlite3 with parameterized placeholders.
If they push back: If they call that amateur: zero-ops MVP on a campus laptop. Scale path is Postgres. Do not say we run Postgres today.
Q6. How do you detect paypa1.com?
Say: Known phishing fragment list, leet table where digit 1 maps toward L, and Levenshtein distance to paypal. Combined with TLD and brand rules. That is lookalike detection, which is the heart of SIH1454.
If they push back: If they type paypal.com: official domain, trusted path, should be LOW if DNS exists.
Q7. Do you handle homoglyphs?
Say: Limited Cyrillic-to-Latin mapping inside the URL checker. Not a full Unicode IDN suite. We say limited on purpose.
If they push back: If they push punycode: we normalize the URL and score the host. Full IDNA hardening is not specified as complete in this build.
Q8. Why not blacklist only?
Say: Feeds lag. A new sbi-login.xyz can steal OTPs for hours before OpenPhish lists it. We add heuristics, brand distance, and psychology on the message text.
If they push back: If they say blacklists are enough: absence from a feed is no_match, not SAFE.
Q9. Why not ML only?
Say: We do not have a curated labelled production dataset yet. A black box fails viva. Parents need a sentence they can act on, not a silent probability.
If they push back: If they want F1: we have no official product F1. Closed-world scripts must be labelled simulations if mentioned at all. Prefer not to quote a percentage.
Q10. Is no_match safe?
Say: No. It means the feed was queried and nothing was found. Zero-day phishing will miss. We still run heuristics and brand checks.
If they push back: If they say then why use feeds: confirmed hits become floors so they cannot be averaged away.
Q11. What does unavailable mean?
Say: A feed timed out or errored. It is not no_match and it is not SAFE. The extension treats backend-down the same way: UNAVAILABLE, never SAFE.
If they push back: If they ask what the user sees: we do not auto-open. Dangerous default is keep closed.
Q12. Can psychology mark CRITICAL alone?
Say: No. If psychology is high and URL, domain, intel, brand, and community are all weak, fused score is capped at 35, which is LOW or MEDIUM. A sale SMS that says act now is not phishing.
If they push back: If they paste a bank OTP SMS with sbi-login.xyz: that is not psychology alone. The lookalike URL carries it.
Q13. Are community reports proof?
Say: No. Signal only, weight 0.05 in fusion. Logged-in users, rate limited: one URL per 24 hours per user, twenty reports per day. Not a court document.
If they push back: If they ask about brigading: that is why the caps exist. Still a prototype control, not a full abuse desk.
Q14. Does HTTPS mean the site is genuine?
Say: No. A padlock is encryption. Certificates are cheap. Fake SBI pages routinely have HTTPS. We even add a little risk if HTTPS is missing, but presence of HTTPS does not make it safe.
If they push back: If they show a green lock on a phish kit: that is the India story. OTP still leaves.
Q15. Do you visit the phishing page?
Say: Not to decide threat intel. Ads and clutter fetch is skipped if intel already confirmed, so we do not load the kit. QR does not visit. Shortener unwrap uses an SSRF guard.
If they push back: If they want screenshots of live kits: we refuse in the jury room. Use lookalikes and screenshots already saved.
Q16. What is SSRF protection?
Say: When we fetch an attacker-controlled URL, we block localhost, private RFC1918, and cloud metadata 169.254.169.254. That stops the scanner from becoming an open proxy into the campus network.
If they push back: If they ask for the file: backend/app/services/ssrf.py.
Q17. Does the extension read WhatsApp?
Say: Only visible links on WhatsApp Web after the page rendered. No native WhatsApp. No phone SMS. Chrome cannot read the phone.
If they push back: If they want Android SMS: planned companion, not implemented. mobile_source is not a live ingest.
Q18. Do you OAuth Gmail?
Say: No. Paste the email text, or type From and Reply-To, or scan visible links. Sender analysis only works if the user types those fields.
If they push back: If they say that is weak: it is an honest browser limit plus privacy. Inbox OAuth is roadmap if legally allowed.
Q19. Is QR a malware scanner?
Say: We decode the payload with OpenCV. We do not execute it. Then we score extracted URLs with the same engine. Destination is not fetched.
If they push back: If decode fails: say so. Try a clearer PNG, or paste the URL.
Q20. What about OCR?
Say: Optional Tesseract. If it is not installed on that PC, paste the text or use the QR tab. Partial, not a claim of full screenshot reading.
If they push back: Do not say we always read the screenshot.
Q21. How do you avoid burning YouTube?
Say: Official Google, YouTube, GitHub are trusted destinations. A dump row for one /watch video does not match every video. Query must overlap on generic paths. User-content hosts — sites.google.com, github.io — stay fully scanned.
If they push back: If they type youtube.com: expect LOW unless confirmed intel wins, which is rare and we still allow confirmed intel to win.
Q22. Are fusion weights optimal?
Say: No. They are documented starting defaults that sum to 1.0. We can change DEFAULT_WEIGHTS. We do not claim a grid-search paper.
If they push back: If they want proof: show risk_engine.py and say starting defaults.
Q23. SQL injection?
Say: Parameterized queries with question-mark placeholders. We do not concatenate user URLs into SQL strings.
If they push back: If they ask ORM: SQLAlchemy is in requirements and unused for live queries. Do not pretend we run an ORM today.
Q24. How are passwords stored?
Say: bcrypt via passlib. JWT HS256 after login. Token in localStorage key cg_token. Prototype, not a bank-grade KMS.
If they push back: If they want refresh tokens and rotation: not specified as implemented.
Q25. CORS?
Say: allow_origins star. Prototype limitation. Say it before they find it. Production must lock origins.
If they push back: Do not say we are production hardened.
Q26. Where is the blockchain?
Say: Theme includes cybersecurity. Phishing intelligence does not require a ledger for this MVP. We did not implement smart contracts.
If they push back: One sentence, then stop. Do not lecture on Ethereum.
Q27. What accuracy do you claim?
Say: None as a product guarantee. No official F1. Model confidence is agreement, not accuracy. We will not say 99 percent.
If they push back: If a teammate quoted a simulation: label it closed-world, stubbed network, not production.
Q28. Who is the user?
Say: Two people. A parent or first-time UPI user sees Simple View: do not enter OTP. A CSE student or campus analyst sees Technical View: providers, registered domain, tags.
If they push back: Do not say only CISOs. Do not say we arrest gangs.
Q29. What is future work?
Say: PostgreSQL, a trained model on curated reports, Android SMS companion, inbox OAuth if legally allowed, global API rate limit, CORS lockdown.
If they push back: Do not sell future work as built.
Q30. Why SQLite?
Say: Zero-ops MVP, one file, campus demo, init_db on API start. Charts read real rows. Scale later with Postgres.
If they push back: If the dashboard is empty: the API was not started, so the file was not initialized.
Q31. Why Manifest V3?
Say: Chrome requirement. Service worker. We cannot use MV2 blocking webRequest the old way, so we use a gate page: scan first, then open or refuse.
If they push back: Admit the omnibox blank-flash limit in the same sentence.
Q32. Is Advisor a chatbot?
Say: No. Static FAQ. There is no LLM classifier and no ChatGPT inside the app.
If they push back: If they used ChatGPT to write slides: tools helped; we own the design and the honesty.

If they push back: Do not say we store nothing.

Say: Logged-in Mark Scam, Risky, or Safe increments domain_reputation counters. Small fusion weight. Signal, not proof.
If they push back: If they mark Google as scam: rate limits plus trusted-domain logic. Still a prototype.

Say: URL path uses decision_engine so intel cannot be averaged away. Message path uses weighted fuse, then raises a floor if a child URL was confirmed malicious.
